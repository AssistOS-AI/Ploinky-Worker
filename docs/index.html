What it is for

Put repeatable model work on rails.

Ploinky Workers is useful when the shape of a task is known, but the inputs keep changing. It keeps model selection, execution, and observation in one place.

▤

Document processing

Extract fields, classify text, normalize records, summarize sections, or run a follow-up validation phase over many inputs.

⌁

Code and file workflows

Read and write text files under a caller-chosen working directory. Keep each task's variables and progress separate.

⇢

Background jobs

Return a task ID immediately, then ask for the current phase, final result, or error whenever your client is ready.

▦

Bulk requests

Queue many tasks, flush them together, and combine compatible phase requests into one structured model prompt.

◉

Provider routing

Ask for a logical tier such as tiny or good. Configure its actual provider and model once in the CLI.

◎

Local inference

Use an existing local endpoint or start a configured local model through the proxy. The same task format works with remote APIs.

Core concepts

A task is a small flow, not a wandering agent.

A natural-language request can be compiled into a cached .mjs task file. You can also write the task file yourself and review every phase.

01 / INPUT

Supply the task

Pass a text request or a JavaScript module, plus start-phase input and an optional working directory.

02 / PHASES

Advance explicitly

Each phase has a tier or no model, a prompt template, and code that chooses the next phase or ends the task.

03 / PROXY

Route and control

The local proxy resolves tiers, applies provider limits, records traffic, and caches complete repeat requests.

04 / RESULT

Inspect the outcome

Wait for the result or return an ID. Status reports the current phase and persists the final result.

Task anatomy

Readable steps you can own.

A phase can call a model, transform its answer, and pass state forward. A model-free phase can perform file work or finish with a structured value.

  • tier names a configured capability, not a hard-coded model.
  • template inserts task variables such as $input.
  • code uses this.next(), this.end(), and confined file methods.
  • currentWorkingDirectory is the exact directory supplied by the caller.
example-task.mjs
export default {
  begin: {
    tier: 'tiny',
    template: 'Extract a short title from: $input',
    code: 'this.title = result; this.next("save")'
  },
  save: {
    tier: null,
    code: `await this.writeFile(
      "title.txt", this.title
    ); this.end({ title: this.title })`
  }
};
Batching

Pack repeated work. Keep results separate.

When a phase opts into batching and its tier enables it, compatible tasks can share one prompt. Pworker gives each item an ID, asks for a JSON result map, and routes each answer back to the right task before execution continues.

What works today

Explicit queue and flush; prompt-level aggregation when the phase template ends in one $variable; one model request for a compatible group; independent per-task results and status.

Where GPU batching fits

The same queue, tier, and ID-based dispatch approach can support GPU batching with a compatible local inference server and scheduler. Actual GPU execution batching depends on that server's capabilities and configuration.

↗
Batching can reduce the number of API requests. It does not automatically reduce token use or latency, and prompt packing is distinct from provider Batch APIs and server-side GPU scheduling.
Operation

Made to run, inspect, and adjust.

Configuration is interactive, while the same capabilities remain scriptable from the CLI and library.

◇

Connect first

The menu accepts a provider API key, an OpenAI-compatible endpoint, or a managed local model. Tier setup appears after a provider is connected and lists its live models.

◷

Observe work

pworker --status lists detached tasks. A task ID retrieves its current phase, completed result, or error after the original process exits.

▣

Keep control

Provider keys and runtime files live under ~/.pworker. Rate limits, response caching, request counts, and bytes transferred are visible through the proxy.

Get started

One program, a few clear commands.

Requires Node.js 22.13 or newer. Open the interactive menu to connect a provider and map a model to a tier. Press Esc to cancel a menu step. Provider credentials are checked against the live model catalog; tier mappings are saved after their final confirmation.
